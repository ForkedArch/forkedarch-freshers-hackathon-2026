# 🚀 ForkedArch Freshers Hackathon 2026

### Build. Explain. Ship.

**Organized by ForkedArch**  
**For:** KUET CSE 2K25 — 1-1 Students  
**Format:** Fully Online  
**Duration:** 50 Hours

## ⚡ The Challenge

You've got a problem. You've got a team of four. You've got **50 hours**. Now build something.

The ForkedArch Freshers Hackathon gives KUET CSE 2K25 students a first experience of building a complete software solution under a real deadline.

## ⏱️ 50 Hours

- **48 hours** — development
- **2 hours** — final submission
- **50 hours total**

The exact timestamps will be announced by ForkedArch.

## 👥 Team Formation

Each team must contain **exactly 4 students**. All members must be KUET CSE 2K25 — 1-1 students.

Teams with **at least one female team member** receive a **5% boost to their final judging score**.

## 📩 How It Works

1. Register your team.
2. After confirmation, receive your problem statement and challenge details by email.
3. Build for 48 consecutive hours.
4. Use the additional 2-hour submission window.
5. Submit your GitHub repository, README, presentation video, and demo where applicable.
6. Judges evaluate the project.
7. Results are announced.

## 💻 Technology Freedom

There is no mandatory technology stack. Use any appropriate language, framework, library, database, API, cloud platform, development environment, or other legitimate tool.

## 🤖 AI Is Allowed

AI-assisted development is allowed, including ChatGPT, GitHub Copilot, Gemini, Claude, Cursor, and similar tools.

> **If you submit it, you should understand it.**

Your README must clearly explain architecture, workflow, important implementation decisions, testing/QA, and significant AI usage. Judges may ask questions to verify understanding.

## 📖 Mandatory README

Every project must contain a clear `README.md` covering:

- Project overview
- Problem statement
- Proposed solution
- Features
- Technology stack
- Architecture
- Complete workflow
- Setup instructions
- Environment variables
- API/database details where applicable
- AI usage
- Testing and quality assurance
- Limitations
- Future improvements

## 🎥 Presentation Video

Every team must submit a **video under 3 minutes** explaining:

**Problem → Solution → Features → Technology → Workflow → Demo**

## 🐙 GitHub

Every project must be pushed to GitHub. Teams should use Git throughout the hackathon and maintain meaningful development history.

## 🏆 Judging

| Criteria | Weight |
|---|---:|
| Problem Understanding & Impact | 20% |
| Innovation & Creativity | 20% |
| Technical Implementation | 25% |
| UI/UX & Usability | 15% |
| Completeness & Quality Assurance | 10% |
| Presentation & Communication | 10% |
| **Total** | **100%** |

Eligible teams receive the applicable 5% female-member score boost after standard judging.
